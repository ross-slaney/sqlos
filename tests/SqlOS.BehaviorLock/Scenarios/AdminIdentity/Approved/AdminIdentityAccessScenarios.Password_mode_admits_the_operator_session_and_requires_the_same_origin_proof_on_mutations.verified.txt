# SqlOS behavior lock transcript
scenario: AdminIdentityAccessScenarios.Password_mode_admits_the_operator_session_and_requires_the_same_origin_proof_on_mutations
profile: dashboard-password

## 1. operator: the signed-in operator lists users with the session cookie
> GET /sqlos/admin/auth/api/users
> Cookie: SqlOS.Dashboard.Session={cookie#1}
< 200 OK
< Content-Type: application/json; charset=utf-8
    {
      "data": [],
      "hasNextPage": false,
      "nextCursor": null,
      "pageSize": 10
    }

## 2. stranger: without the session cookie the admin API is not found
> GET /sqlos/admin/auth/api/users
< 404 Not Found

## 3. stranger: a proof without the session cookie is still not found
> POST /sqlos/admin/auth/api/users
> Content-Type: application/json; charset=utf-8
> Origin: https://sqlos.example.test
> X-SqlOS-Request: 1
>   {
>     "displayName": "Stranger",
>     "email": "{email:stranger}"
>   }
< 404 Not Found

## 4. operator: a cookie-authenticated mutation without X-SqlOS-Request is rejected
> POST /sqlos/admin/auth/api/users
> Content-Type: application/json; charset=utf-8
> Cookie: SqlOS.Dashboard.Session={cookie#1}
>   {
>     "displayName": "Missing",
>     "email": "{email:missing}"
>   }
< 403 Forbidden
< Cache-Control: no-store
< Content-Type: application/json; charset=utf-8
    {
      "error": "csrf_rejected",
      "message": "The request could not be verified."
    }

>   {
>     "displayName": "Referer",
>     "email": "{email:referer}"
>   }

    {

      "isActive": true,
      "updatedAt": "{datetime:utc-z}"
    }
