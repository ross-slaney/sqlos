`IHasResourceId` is the lower-level contract authorized pages read. It exposes the FGA resource ID on a domain entity so `ToPageAsync` can check each app row against the resources the subject can access.

```csharp
public interface IHasResourceId
{
    string ResourceId { get; }
}
```

For protected domain entities whose resource lifecycle should be managed by SqlOS, prefer `ISqlOSResourceEntity`. It extends `IHasResourceId` with resource metadata used by `SqlOSDbContext<TContext>` during `SaveChanges` / `SaveChangesAsync`.

```csharp
public sealed class Workspace : ISqlOSResourceEntity
{
    public Guid Id { get; set; }
    public string ResourceId { get; set; } = "";
    public string Name { get; set; } = "";
    public string OrganizationId { get; set; } = "";

    public string ResourceTypeId => "workspace";
    public string ResourceName => Name;
    public string ParentResourceId => $"org::{OrganizationId}";
    public string? ResourceDescription => null;
    public bool ResourceIsActive => true;
}
```

`ToPageAsync` uses `ResourceId` to return only the rows whose resource the subject can access, one page at a time:

```csharp
var page = await db.Workspaces
    .OrderBy(x => x.Name)
    .ToPageAsync(subjectId, "WORKSPACE_VIEW", pageSize: 20, cursor, ct);
```

`T` must implement `IHasResourceId`, and the query must start from a `DbSet` of a context deriving from `SqlOSDbContext<TContext>`. For one row, pass its `ResourceId` to `CheckAccessAsync`.

Use plain `IHasResourceId` directly for lower-level/manual resources where your application owns the FGA resource lifecycle. Use `ISqlOSResourceEntity` for the normal SDK path.

## The node index, and optional page orders

Every entity that implements `IHasResourceId` in a `SqlOSDbContext<TContext>` gets a node index: a table of SqlOS's own (`SqlOSFgaPage_Workspaces_Id`) listing which rows sit under which node of the resource tree. Your next migration creates it, and SqlOS keeps it current on every save. `ToPageAsync` reads it to page any order at a cost bounded by the rows the caller can see.

To make one sort about a page for any caller, declare it next to the entity's mapping, and SqlOS also keeps a copy of that order under every node:

```csharp
modelBuilder.Entity<Workspace>(entity =>
{
    entity.HasKey(x => x.Id);
    entity.Property(x => x.Name).HasMaxLength(200);
    entity.HasPageOrder(x => x.Name);   // optional: (Name, Id)
});
```

`ResourceId` stays the only connection between your table and SqlOS: the node index and the declared order live in tables of SqlOS's own (`SqlOSFgaPage_Workspaces_Id`, `SqlOSFgaPage_Workspaces_Name`). Order columns are non-nullable, strings need a maximum length, and the entity needs a single-column primary key. See [Optimizing page performance](/docs/guides/optimizing-page-orders).
