`IHasResourceId` is the lower-level contract used by authorization filters. It exposes the FGA resource ID on a domain entity so query filters can join app rows to accessible resources.

```csharp
public interface IHasResourceId
{
    string ResourceId { get; }
}
```

For protected domain entities whose resource lifecycle should be managed by SqlOS, prefer `ISqlOSResourceEntity`. It extends `IHasResourceId` with resource metadata used by `SqlOSDbContext<TContext>` during `SaveChanges` / `SaveChangesAsync`.

```csharp
public sealed class Workspace : ISqlOSResourceEntity
{
    public Guid Id { get; set; }
    public string ResourceId { get; set; } = "";
    public string Name { get; set; } = "";
    public string OrganizationId { get; set; } = "";

    public string ResourceTypeId => "workspace";
    public string ResourceName => Name;
    public string ParentResourceId => $"org::{OrganizationId}";
    public string? ResourceDescription => null;
    public bool ResourceIsActive => true;
}
```

When you call `BuildFilterAsync<T>`, the filter uses `ResourceId` to restrict the query to resources the subject can access:

```csharp
var filter = await authService
    .BuildFilterAsync<Workspace>(subjectId, "WORKSPACE_VIEW");

var workspaces = await db.Workspaces
    .Where(filter)
    .OrderBy(x => x.Name)
    .ToListAsync(ct);
```

Use plain `IHasResourceId` directly for lower-level/manual resources where your application owns the FGA resource lifecycle. Use `ISqlOSResourceEntity` for the normal SDK path.

## Declare the orders a list is paged by

A list endpoint pages with `ToPageAsync`. Declare each order it pages by next to the entity's mapping, and SqlOS keeps a copy of that order under every node of the resource tree, so a page costs about a page for any caller:

```csharp
modelBuilder.Entity<Workspace>(entity =>
{
    entity.HasKey(x => x.Id);
    entity.Property(x => x.Name).HasMaxLength(200);
    entity.HasPageOrder(x => x.Name);   // (Name, Id)
});

var page = await db.Workspaces
    .OrderBy(x => x.Name)
    .ToPageAsync(filter, pageSize: 20, cursor, ct);
```

`ResourceId` stays the only connection between your table and SqlOS: the declared order lives in a table of SqlOS's own (`SqlOSFgaPage_Workspaces_Name`) that your next migration creates. Order columns are non-nullable, strings need a maximum length, and the entity needs a single-column primary key. See [Paginating authorized lists](/docs/guides/paginating-authorized-lists).
