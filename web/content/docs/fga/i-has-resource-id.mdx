`IHasResourceId` is the contract authorization filters use. It exposes the row's FGA resource ID, which `BuildFilterAsync` checks against the resources the subject may see. See [Set up FGA](/docs/fga/setup) for both ways to add it to an application.

```csharp
public interface IHasResourceId
{
    string ResourceId { get; }
}
```

`ResourceId` holds the row's FGA resource; map it as an ordinary property and set it before the row is saved. It is the only thing the filter needs from your table, and the only column SqlOS touches there: if you declared no index on it, SqlOS adds one to the EF model (`IX_{Table}_SqlOSFgaResourceId`) and your migration creates it.

For protected domain entities whose resource lifecycle should be managed by SqlOS, derive from `SqlOSResourceEntity` (or implement `ISqlOSResourceEntity`, which it implements for you). It extends `IHasResourceId` with resource metadata used by `SqlOSDbContext<TContext>` during `SaveChanges` / `SaveChangesAsync`, and the base class carries `ResourceId` so the entity declares nothing:

```csharp
public sealed class Workspace : SqlOSResourceEntity
{
    public Guid Id { get; set; }
    public string Name { get; set; } = "";
    public string OrganizationId { get; set; } = "";

    public override string ResourceTypeId => "workspace";
    public override string ResourceName => Name;
    public override string? ParentResourceId => $"org::{OrganizationId}";
}
```

When you call `BuildFilterAsync<T>`, the filter uses `ResourceId` to restrict the query to resources the subject can access:

```csharp
var filter = await authService
    .BuildFilterAsync<Workspace>(subjectId, "WORKSPACE_VIEW");

var workspaces = await db.Workspaces
    .Where(filter)
    .OrderBy(x => x.Name)
    .ToListAsync(ct);
```

Use plain `IHasResourceId` directly for lower-level/manual resources where your application owns the FGA resource lifecycle. Use `SqlOSResourceEntity` — or `ISqlOSResourceEntity`, when the entity's base class is spoken for — for the normal SDK path.
