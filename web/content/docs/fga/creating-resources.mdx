The recommended path for protected application rows is to make the EF entity implement `ISqlOSResourceEntity`. When the app derives its DbContext from `SqlOSDbContext<TContext>`, SqlOS creates, updates, and deletes the backing `SqlOSFgaResource` row during `SaveChanges` / `SaveChangesAsync`.

## Entity-backed resources

```csharp
public sealed class Workspace : ISqlOSResourceEntity
{
    public Guid Id { get; set; }
    public string ResourceId { get; set; } = "";
    public string Name { get; set; } = "";
    public string OrganizationId { get; set; } = "";

    public string ResourceTypeId => "workspace";
    public string ResourceName => Name;
    public string ParentResourceId => $"org::{OrganizationId}";
    public string? ResourceDescription => null;
    public bool ResourceIsActive => true;
}
```

Assign a stable `ResourceId` before saving the entity:

```csharp
var workspaceId = Guid.NewGuid();
var workspace = new Workspace
{
    Id = workspaceId,
    ResourceId = $"workspace::{workspaceId:D}",
    OrganizationId = organizationId,
    Name = request.Name.Trim()
};

db.Workspaces.Add(workspace);
await db.SaveChangesAsync(ct);
```

`SqlOSDbContext<TContext>` validates the resource type, parent resource, self-parenting, and obvious cycles before it writes the `SqlOSFgaResource` row.

## Manual resources

Use manual resource APIs only for resources that are not represented by an application entity, such as tenant roots, organization roots, or external resources.

```csharp
await db.ProvisionResourceWithIdAsync(
    $"org::{organization.Id}",
    resourceTypeId: "organization",
    name: organization.Name,
    parentResourceId: "root",
    isActive: organization.IsActive,
    cancellationToken: ct);
```

For strict creates, use `CreateResourceAsync(...)` or `CreateResourceWithIdAsync(...)`. For deletes, use `DeleteResourceAsync(...)`; it deletes the resource and revokes its direct grants (audited as `fga.grant.revoked` with the reason `resource_deleted`), but it does not cascade child resources. To move a resource or change whether it is active, provision it again with the new `parentResourceId` or `isActive`.

Every helper validates the change before it tracks it: the resource type must exist, the parent must exist (or be an entity this unit of work is adding), and the resource can be neither its own ancestor nor deeper than the configured maximum hierarchy depth. The lower-level `CreateResource(parentId, ...)` checks the same, so an unknown parent fails when you call it, not later as a database error on save.

`SqlOSFgaResource` properties are read-only; resources change only through these helpers and entity-backed sync. Moves, activity changes, and deletions are audited (`fga.resource.moved`, `fga.resource.deactivated` or `fga.resource.reactivated`, `fga.resource.deleted`).
