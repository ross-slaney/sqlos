  FGA is the authorization half of SqlOS. Roles and grants live on resources, child resources inherit access, and list endpoints read one authorized page in SQL instead of post-processing rows in memory.
</Banner>

FGA models resources as a tree. You grant roles on a node. Child nodes inherit access. A list endpoint reads one authorized page from SQL Server or PostgreSQL; a detail endpoint checks one resource. You do not load everything and filter in memory.

![A root administrator sees both workspaces, a team grant reaches one workspace's documents, and a guest grant reaches only its shared document.](/docs/fga-resource-tree.png)

[Designing your resource tree](/docs/fga/designing-your-resource-tree) explains grant placement, groups, and query performance, including what a page costs. [Paginating authorized lists](/docs/guides/paginating-authorized-lists) covers `HasPageOrder` and `ToPageAsync`.

## How it works

Define resources (projects, chains, stores), roles (admin, viewer), and permissions (VIEW, EDIT). Grant a role to a user on a resource. Every descendant of that resource inherits the grant.

## Reading authorized data

<Tabs defaultValue="pages">
  <TabsList>
    <TabsTrigger value="pages">Pages</TabsTrigger>
    <TabsTrigger value="checks">Point checks</TabsTrigger>
  </TabsList>

  <TabsContent value="pages">
    The core feature. Instead of loading all records and filtering in memory, a list endpoint reads one authorized page of its EF Core query:

    ```csharp
    var page = await dbContext.Chains
        .OrderBy(c => c.Name)
        .ToPageAsync(subjectId, "CHAIN_VIEW", pageSize: 20, cursor, ct);

    return Results.Ok(page.ToResponse(c => new ChainDto(c.Id, c.Name)));
    ```

    Users only see rows they may access. SqlOS checks rows with the recursive authorization function on SQL Server or PostgreSQL. Declare the order with `HasPageOrder(c => c.Name)` and a page costs about a page for any caller. SqlOS has no authorized count or join, because those cost every row the caller can see; page instead. See [Authorized pages](/docs/fga/list-filter).
  </TabsContent>

  <TabsContent value="checks">
    For a single action on one resource, do an explicit point check:

    ```csharp
    var access = await authService.CheckAccessAsync(subjectId, "CHAIN_EDIT", resourceId);

    if (!access.Allowed)
        return Results.Json(new { error = "Permission denied" }, statusCode: 403);
    ```
  </TabsContent>
</Tabs>

## Key concepts

| Concept | Description |
| --- | --- |
| [Resource](/docs/fga/resource-hierarchy) | A node in the hierarchy (org, project, store) |
| [Subject](/docs/fga/subject-types) | Who is being authorized (user, agent, service account) |
| [Role](/docs/fga/roles) | A named set of permissions (viewer, editor, admin) |
| [Permission](/docs/fga/permissions) | A capability key (CHAIN_VIEW, INVENTORY_EDIT) |
| [Grant](/docs/fga/grants) | Links subject + role + resource; inherits downward |
