>
  FGA is the authorization half of SqlOS. Roles and grants live on resources, child resources inherit access, and EF queries get translated into SQL-backed authorization filters instead of post-processing rows in memory.
</Banner>

FGA models resources as a tree. You grant roles on a node, and access flows to descendants through active resources. SQL Server or PostgreSQL filters, orders and pages the data in one statement; nothing is loaded into application memory to be trimmed there.

![A team grant on Workspace A reaches Documents A and B. The same document query returns all four documents for a root administrator, A and B for the team, and only D for a guest with a direct grant.](/docs/fga-resource-tree.png)

For a document editor, grant the owner access to a workspace and place their documents beneath it. New documents inherit access without a grant per document. A team → inspection → item hierarchy works the same way. These are access boundaries, not special resource types required by SqlOS.

<Callout type="info" title="Modeling decisions are part of the design">
  Grant at the highest node that matches the intended access, use groups for shared responsibilities, and keep large subtree moves deliberate. A page costs about the page for a caller who sees most of the table and about the caller's rows for one who sees few; in between, the worst page grows with the square root of the table. A caller granted on many separate branches pays one index range per branch, up to a cap set by the table's size. Filters and aggregates keep their normal database costs. Read [Designing your resource tree](/docs/fga/designing-your-resource-tree) before choosing your hierarchy.
</Callout>

## How it works

Define resources (projects, chains, stores), roles (admin, viewer), and permissions (VIEW, EDIT). Grant a role to a user on a resource. Every descendant of that resource inherits the grant.

## Query-time filtering

<Tabs defaultValue="filters">
  <TabsList>
    <TabsTrigger value="filters">Query filters</TabsTrigger>
    <TabsTrigger value="checks">Point checks</TabsTrigger>
  </TabsList>

  <TabsContent value="filters">
    The core feature. Instead of loading all records and filtering in memory, FGA pushes authorization into the SQL query:

    ```csharp
    var filter = await authService
        .BuildFilterAsync<Chain>(subjectId, "CHAIN_VIEW");

    var chains = await dbContext.Chains
        .Where(filter)
        .OrderBy(c => c.Name)
        .ToListAsync();
    ```

    Users only see rows they may access. The filter is a SQL predicate over the resource tree's closure, and the whole query is one statement; add an order and a `Take` for a page. See [Paginating authorized lists](/docs/guides/paginating-authorized-lists).
  </TabsContent>

  <TabsContent value="checks">
    For a single action on one resource, do an explicit point check. It reads the resource's lineage in one query:

    ```csharp
    var access = await authService.CheckAccessAsync(subjectId, "CHAIN_EDIT", resourceId);

    if (!access.Allowed)
        return Results.Json(new { error = "Permission denied" }, statusCode: 403);
    ```
  </TabsContent>
</Tabs>

## Setup

Derive your context from `SqlOSDbContext<TContext>` (or call `modelBuilder.UseSqlOS(Database.ProviderName)` last in your own `OnModelCreating`), declare `ResourceId` on each protected entity, and register SqlOS with your database provider:

```csharp
builder.AddSqlOS<AppDbContext>(
    db => db.UseSqlServer(connectionString));   // or db.UseNpgsql(connectionString)

var app = builder.Build();
```

[Set up FGA](/docs/fga/setup) walks through both ways, on SQL Server and on PostgreSQL.

## Key concepts

| Concept | Description |
| --- | --- |
| [Resource](/docs/fga/resource-hierarchy) | A node in the hierarchy (org, project, store) |
| [Subject](/docs/fga/subject-types) | Who is being authorized (user, agent, service account) |
| [Role](/docs/fga/roles) | A named set of permissions (viewer, editor, admin) |
| [Permission](/docs/fga/permissions) | A capability key (CHAIN_VIEW, INVENTORY_EDIT) |
| [Grant](/docs/fga/grants) | Links subject + role + resource; inherits downward |
