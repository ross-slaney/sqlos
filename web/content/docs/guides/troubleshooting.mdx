You'll learn how to diagnose connection, OAuth callback, SAML, and migration problems quickly.

![Troubleshooting flow from symptom through configuration, runtime, and persisted evidence](/docs/guides-troubleshooting.svg)

## SQL Server connection

**Symptom:** App fails at startup with connection string errors.

- Confirm `ConnectionStrings:DefaultConnection` is set for your host and sample.
- For Todo AppHost, wait for the SQL container to become healthy before hitting the API.
- Use `TrustServerCertificate=True` for local dev containers if needed.

## SqlOS tables missing

**Symptom:** EF or raw SQL errors referencing `SqlOS_*` tables.

- Ensure the host has started with `AddSqlOS<TContext>(...)` registered. Schema bootstrap runs from the SqlOS hosted service during startup; the HTTP routes SqlOS maps at startup do not create the schema.
- If your migrations run first, call `SqlOSBootstrapper.InitializeAsync()` before migrating (see [Configuration](/docs/guides/configuration#schema-ownership)).

## OAuth redirect / callback mismatch

**Symptom:** `redirect_uri_mismatch` or `invalid_redirect_uri`.

- Registered redirect URI must **exactly** match the request (scheme, host, port, path).
- For OIDC social login, update both the IdP console **and** the SqlOS connection’s allowed callbacks after you know the `connectionId`.

## Dashboard login

**Symptom:** Cannot access `/sqlos/admin/auth/`.

- Check the `options.Dashboard.AuthMode` and `options.Dashboard.Password` values assigned in your `AddSqlOS` callback. SqlOS does not bind the `SqlOS` configuration section automatically.
- After repeated failures, dashboard throttling may return `429` — wait for the lockout window.

## SAML

**Symptom:** SAML login fails or loops.

- Verify Entity ID and ACS URL match what the IdP expects.
- Confirm org **primary domain** matches user email for [home realm discovery](/docs/authserver/home-realm-discovery).
- Rotate IdP signing certificates in the dashboard when the IdP rolls keys.
- Compare clock skew if assertions are rejected as expired.

**Symptom:** Users expected SSO but see password login.

- Domain on the org must match the email entered at login.
- SAML connection must be **enabled**, not draft-only.

## Email or phone OTP delivery

Open **Auth Server > Security > OTP communications readiness** first. The status returns bounded reason codes such as `missing_from_address`, `missing_auth_token`, or `missing_verify_service_sid` without exposing provider credentials. Deployment-owned values must be corrected in host configuration and the application restarted; the dashboard intentionally does not persist them.

Use **Send test delivery** only with an operator-controlled destination. A test is limited to three sends per destination per hour and creates no SqlOS login challenge. Recent rows distinguish a local configuration problem, provider rejection, and administrative test throttling while retaining only a masked destination. Runtime user-facing OTP errors remain generic.

## Authorized pages are empty

- Confirm resources were created for domain rows and grants exist for the subject.
- Permission key in code must match seeded permission keys exactly. An unknown subject or permission returns an empty page and logs a warning under `SqlOS.Fga`.
- Use the access tester in `/sqlos/admin/fga/` to reproduce the check for one row.

## A list is slow for some callers

Turn on Debug logging for the `SqlOS.Fga` category. Each page logs one line:

```text
ToPageAsync Product by CreatedAt, Id desc (page order not declared): 6 round(s); read 1 rows per round [20, 80, 320, 1280, 5120, 20480]; read 2 entries per node per round []; read 3 keys per round [21, 81, 321, 1281, 5121, 20000]; page from read 3; 0 row(s) dropped by the final check; 210 ms.
```

A page by an order no `HasPageOrder` declares reads up to about nine times the caller's rows, or the query's rows up to the page, whichever is smaller. Many rounds ending `page from read 3` mean the caller's rows are many and sit far into the order. If that list and sort are hot, declare the order the line names, `modelBuilder.Entity<Product>().HasPageOrder(p => p.CreatedAt)`, and add a migration; the next start fills the new table and the page costs about a page. See [Optimizing page performance](/docs/guides/optimizing-page-orders).

## Pages are missing rows

- Rows written outside EF Core (bulk loads, raw SQL, `ExecuteUpdate`/`ExecuteDelete`, triggers) have no node index or page-order entries until you call `ISqlOSFgaAuthService.RebuildPageOrdersAsync()`.
- After a rolling deployment that added a node index or declared a new order, rows that instances on the previous version wrote have no entries. Call `RebuildPageOrdersAsync()` once every instance runs the new version.
- A startup warning `Node index ...: table ... does not exist` or `Page order ...: table ... does not exist` means the migration that creates the table has not been applied. Pages still return the right rows, by reading the table in order.
- A startup warning `... implements IHasResourceId but has no node index` names why the entity cannot have one (an owned type, a view, TPT or TPC inheritance, no single-column primary key, or no mapped `ResourceId`). Its pages read the table in order.
- The context must derive from `SqlOSDbContext<TContext>`; a hand-rolled `ISqlOSFgaDbContext` does not keep page orders current.
