You'll learn how to build an FGA filter and apply it in EF Core queries for list and detail endpoints.

<Callout type="info" title="Prerequisites">
  - FGA model seeded and resources created for your data
  - `ISqlOSFgaAuthService` available in your API
</Callout>

## Goal

List endpoints return only rows the current subject may read — in one SQL round-trip.

![FGA Access Tester used to verify the same permission enforced by an EF query filter](/docs/dashboard-access-tester.png)

## Steps

1. **Inject** `ISqlOSFgaAuthService` in your endpoint or service.

2. **Build a filter** for the entity type:

```csharp
var filter = await fgaAuth.BuildFilterAsync<Project>(
    subjectId: userId,
    permissionKey: "project.read");

var projects = await db.Projects
    .Where(filter)
    .Where(p => p.IsActive)
    .OrderBy(p => p.Name)
    .Take(20)
    .ToListAsync();
```

3. **Point checks** for single-resource actions use `CheckAccessAsync` (see [Checking a permission](/docs/fga/checking-a-permission)).

4. **Verify** with the access tester in `/sqlos/admin/fga/`.

## Expected outcome

- LINQ translates to SQL with the FGA TVF in the plan
- Pagination and sorting stay in the database
- No N+1 calls to an external policy engine
