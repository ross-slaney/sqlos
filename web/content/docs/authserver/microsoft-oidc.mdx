## Setup

1. Register an app in [Azure Portal > App Registrations](https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps)
2. Under **Authentication > Web**, add the redirect URI:

```
http://localhost:5062/sqlos/auth/oidc/callback
```

3. Under **Certificates & secrets**, create a client secret
4. Create the OIDC connection in SqlOS:

```bash
curl -X POST http://localhost:5062/sqlos/admin/auth/api/oidc-connections \
  -b "$SQLOS_DASHBOARD_COOKIE_JAR" \
  -H "Content-Type: application/json" \
  -d '{
    "providerType": "microsoft",
    "displayName": "Microsoft",
    "clientId": "YOUR_AZURE_APP_CLIENT_ID",
    "clientSecret": "YOUR_AZURE_APP_CLIENT_SECRET",
    "allowedCallbackUris": [
      "http://localhost:5062/sqlos/auth/oidc/callback"
    ]
  }'
```

5. The create operation enables the connection. Use the endpoint below only to re-enable it after an operator disabled it:

```bash
curl -X POST http://localhost:5062/sqlos/admin/auth/api/oidc-connections/{id}/enable \
  -b "$SQLOS_DASHBOARD_COOKIE_JAR"
```

See [Authenticate operator API calls](/docs/authserver/dashboard-overview#authenticate-operator-api-calls) before using any admin `curl` example.

## Seed from code

To create the connection from a fresh database without the dashboard or curl, seed it at startup:

```csharp
options.AuthServer.SeedMicrosoftConnection(
    clientId: builder.Configuration["SqlOS:Oidc:Microsoft:ClientId"]!,
    clientSecret: builder.Configuration["SqlOS:Oidc:Microsoft:ClientSecret"]!,
    tenant: "common",
    "http://localhost:5062/sqlos/auth/oidc/callback");
```

See [Social sign-in](/docs/guides/social-oidc#seed-from-startup) for seeding behavior and the general `SeedOidcConnection` form.

See [OIDC Social Login](/docs/authserver/oidc-auth) for the complete auth flow.
