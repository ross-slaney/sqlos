---
title: "Identity deletion"
description: "Terminal account and organization deletion with host data cleanup."
---

`SqlOSIdentityDeletionService` is the shared service behind operator deletion and host product flows. Call `DeleteUserAsync(userId, actorId, confirm)` or `DeleteOrganizationAsync(organizationId, actorId, confirm)` only after authorizing the authenticated caller. The operator dashboard and `POST /sqlos/admin/auth/api/users/{id}/delete` / `organizations/{id}/delete` require operator authorization and explicit confirmation. Membership offboarding uses `RemoveMembershipAsync`.

Deletion is terminal. Accounts lose credentials, email/phone sign-in identities, external identity links and memberships; sessions and refresh tokens are revoked through the central lifecycle policy. An inactive anonymous identifier remains for historical attribution and security audit. Organization identities become inactive anonymous records, verified domains are removed, SSO/SCIM is disabled, memberships removed and sessions revoked. Deletion is not an automatic purge of historical audit, diagnostic records, email delivery logs or host application content.

Hosts register `ISqlOSIdentityDeletionParticipant` for last-administrator/ownership safeguards, billing checks and application data cleanup. Participants run before identity changes in the same transaction and may veto by throwing. Use the same scoped EF context; never perform external I/O from participants. A host may hold an enclosing transaction. Idempotent retries return `AlreadyDeleted` without repeating cleanup.

Code-first seeding of a delete operation is not applicable: deletion is an explicit runtime lifecycle action, never desired-state configuration. Services, operator APIs and dashboard share the same participant pipeline. A deleted organization cannot be reactivated through UpdateOrganizationAsync or receive new memberships. Retained identifiers are not credentials.
