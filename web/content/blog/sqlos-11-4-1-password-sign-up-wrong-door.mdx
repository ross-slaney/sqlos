SqlOS 11.4.0 handled the wrong door for email codes. 11.4.1 handles it for passwords.

Until now, a password sign-up for an address that already had an account failed with "The request could not be completed." The real error, that the address was taken, wasn't safe to show as written, so nobody learned what to do.

Now that sign-up goes through the same password check sign-in uses, with lockout, verification and MFA.

- **The account's own password signs it in.** No user, organization, sign-up hook or sign-up audit event is created.
- **Any other password answers "An account already exists for this email. Sign in with its password instead."**

This works the same on the headless API, the hosted AuthPage and the direct JSON signup.

## Upgrade

```bash
dotnet add package SqlOS --version 11.4.1
npm install @sqlos/headless@11.4.1
```

There's no schema change and no new setting. Read [users and credentials](/docs/authserver/users-and-credentials) for the details.
