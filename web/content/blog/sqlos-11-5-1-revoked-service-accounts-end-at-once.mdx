title: "SqlOS 11.5.1: a revoked service account is refused at once"
description: "Revoking a machine client or deleting an organization now ends its service accounts by the database's clock, so the next access check refuses them."
date: "2026-11-25"
author: "Ross Slaney"

Revoking a machine client, revoking a client-credentials client and deleting an organization all end a service account by setting its expiry to now. Until this release SqlOS took "now" from the app server's clock. The access checks compare the expiry with the database server's clock.

When the database's clock read a little behind the app's, a check made in the next few milliseconds could still allow the account. Its credentials were already revoked, so the account could not get a new token. A direct `CheckAccessAsync` for it could still answer yes.

SqlOS 11.5.1 reads the current time from the database when it ends a service account. It uses the same expression the checks use, which is `GETUTCDATE()` on SQL Server and `CURRENT_TIMESTAMP AT TIME ZONE 'UTC'` on PostgreSQL. Every check that runs after the call returns refuses the account.

## Upgrade

```bash
dotnet add package SqlOS --version 11.5.1
npm install @sqlos/headless@11.5.1
```

There's no schema change, no new setting and no API change.
